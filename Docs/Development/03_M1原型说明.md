# M1 初步实现与实验参数

2026 年 10 月 6 日。用户授权在初始项目上传后推进第一阶段；本版围绕废木料的首个纵向流程展开。以下参数仅用于原型验证，不替代原始策划中的待定项。

## 当前可玩的流程

移动到垃圾落点 → 拾取手锯、废木料、连接件 → 搬入仓库 → 在固定预留位置搭建木工台 → 主角持锯在台旁加工木板或木柄 → 产品先进入设备内部、再尝试入库 → 从仓库出售。

垃圾按游戏时间继续落入，输入频率和批量随时间增长。混杂塑料在此阶段作为暂存资源和堆积压力来源，塑料产线在后续阶段接入。露天占地降低台旁人工效率，仓库库存不计压力。

## 操作

| 操作 | 按键／界面 |
|---|---|
| 移动 | WASD／方向键 |
| 拾取附近物品 | E；Shift+E 尽量拾取整堆，背包装不下的留在原地 |
| 入库 | 靠近仓库，Q 或“入库”；手锯默认随身保留 |
| 搭建木工台 | 下方按钮，消耗仓库材料；暂停时先预留材料，恢复后建成 |
| 开工／停工 | F 或下方按钮；连续加工需要主角在台旁及可用手锯 |
| 切换木板／木柄 | 下方配方按钮；当前批次完成后切换 |
| 取出／放下 | 右侧库存对应“取1／放1”；取出需靠近仓库，放下需附近有可用空地 |
| 出售 | 右侧出售 1 件或全部产品；暂停时也可出售 |
| 暂停／加速 | 空格；1／2／4 设置速度，或上方按钮 |
| 重开 | 上方“重开”；清空本局，重新提供开局物资 |

建议先靠近手锯拾取，再收集连接件和木料。右侧同时显示背包与仓库数量；鼠标滚轮可滚动右侧面板，小窗口也能操作出售按钮。

## 实验配置

修改 `Assets/_Game/Data/M1Balance.asset` 后重新进入 Play。配置以 ScriptableObject 保存，每次进入场景时复制，试玩和重开不会修改资产；本局重开沿用本局配置。正常试玩的垃圾随机序列每局变化，自动验证使用固定种子以便复现。

| 项目 | 初始实验值 |
|---|---|
| 地图 | 20×14 格 |
| 背包／仓库／设备产物容量 | 12／40／4 单位；每件物品暂占一单位，包含手锯 |
| 单格露天容量 | 5 单位；压力按占据的格数计算，不按单格数量计算 |
| 木工台建造 | 4 废木料＋2 回收连接件 |
| 木板实验配方 | 2 废木料 → 1 木板，基础 4 游戏秒 |
| 木柄实验配方 | 2 废木料 → 2 木柄，基础 5 游戏秒 |
| 木板／木柄实验售价 | 5／3 金钱，每件 |
| 压力 | 木工台周围半径 5 格；12 格堆积达到最低效率 35% |
| 输入 | 初始基准间隔 22 秒、每批 3 单位；频率及数量按 90 秒成长尺度增加 |

木板与木柄暂用两个独立配方，具体配方是否最终分开仍待确认。出售资格、容量计量、开局供给、岗位距离和实验地图不是正式数值结论。

## 已保持的行为

- 入库和取出只移动能容纳的数量，剩余物品保留在来源处。
- 建造在所有材料足够时才原子扣除；缺少其中一项不扣另一项。
- 每批开工时从仓库预留投入，停工或离开台旁保留投入与进度。
- 缺原料、缺手锯、缺主角或输出堵塞时停止；条件恢复后继续。
- 产物在设备内部保留，占满后不启动下一批。仓库腾出空间后转入并恢复。
- 垃圾增长、加工和移动共用游戏时间，暂停和加速一致生效。
- 场地满时新增垃圾保存在落点积压队列，不丢弃；拾取腾出地面后继续放入。

输入从固定落点优先占据最近可用格，物品不占设施预留格；此阶段主角可穿过露天堆积，不实现路径规划与拥堵绕路。搬运入库需主角到场；仓库向木工台供料与收成暂用直接库存转移，实体运输留到 M3。

## 验证与工具

```powershell
.\Tools\Unity.ps1 -Action Setup
.\Tools\Unity.ps1 -Action Test
.\Tools\Unity.ps1 -Action Build
.\Tools\Unity.ps1 -Action Smoke
```

`Setup` 配置素材并将初始空白 Main 场景转换为原型场景，已有原型场景不会重建；也不重置已有实验数值。`Test` 跑 EditMode 核心规则与资源引用测试。`Build` 输出 Windows 64 位开发原型，`Smoke` 在独立运行包中走一次拾取—搬运—建台—加工—出售—暂停流程，保存 JSON 与截图。

日志在 `Logs/`，测试结果在 `TestResults/`，预览图在 `Artifacts/M1-preview.png`，运行包在 `Builds/Windows/`；均由 UVCS 忽略。源场景、代码、配置和素材应加入 UVCS。

本次验证结果：17 项 EditMode 测试通过；Windows 64 位开发构建通过；独立运行自动流程通过，实际拾取开局物资、搭台、完成 2 批木板并出售获得 5 金钱，同时验证暂停和重开。已检查初始与完成流程的渲染画面、中文标题和操作布局。JSON 流程结果在 `TestResults/standalone-smoke.json`，完成画面在 `Artifacts/M1-preview-completed.png`。

## 素材来源

十张简单像素图由 `Tools/PreparePrototypeArt.py` 的几何绘制生成，包含主角、废木料、塑料、手锯、连接件、木板、木柄、仓库、木工台和地面。仓库等复杂对象保留白盒含义，并用中文标注。

中文字体是 Google Fonts 发布的 [Noto Sans SC](https://github.com/google/fonts/tree/main/ofl/notosanssc) 的静态子集，衍生字体名称为 **Rubbish Prototype Sans**；授权见相邻 `OFL.txt`，构建时也把授权复制到运行包。未使用系统商业字体，因此运行包无需依赖本机微软雅黑。

更新字体时，将 [上游变量字体](https://raw.githubusercontent.com/google/fonts/main/ofl/notosanssc/NotoSansSC%5Bwght%5D.ttf) 下载到 `Artifacts/Fonts/NotoSansSC-variable.ttf`，用 Python 的 fontTools 运行 `Tools/PreparePrototypeFont.py`。字体子集覆盖本仓库脚本和策划中的字符；后续增加新界面字样时需重新生成。几何素材工具需要 Pillow。
