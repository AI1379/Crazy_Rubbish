## 24. 三人团队第一批制作任务（2026-10-10）

### 24.1 人员与首批交付目标

用户确认三名成员按顺序为程序、美工、程序。本章按该顺序分配，姓名未提供，使用成员1、成员2、成员3。Unity工程实际进度、个人熟练程度和最终截止日期仍未确认；首批建议用2个制作日完成，是安排建议，不能据历史“剩17天”推算当前工期。

首批共同交付一个能从新游戏开始操作的首区版本：主角移动、拾取垃圾与工具，建立木料地点，亲手加工，建成发电机并补燃料，连接现有住房／路灯，获得认可后选择招募人数，安排居民供料、加工和归仓，出售木板并支付第一张工资。核心体验是“垃圾变成资源，自己劳动发展为安排他人持续劳动”。

本批验收以这段可操作流程为准，界面与数据需支持后续接入其他玩法。完整游戏仍按三个区域及可达结局要求推进；第二区域、开采和返回工程继续列入后续批次。未完成的功能列在交付说明中，不能把首批原型写成完整比赛作品。

| 人员 | 本批主责 | 负责范围 |
|---|---|---|
| 成员1：程序 | 玩家、库存、建造及经营基础；集成负责人 | 工程、统一时间、物品数据、背包仓库、玩家交互、网格建造、发电电线、出售与工资扣款、公共界面功能 |
| 成员2：美工 | 第一地区视觉与可用界面素材 | 角色、建筑、垃圾与物品图标、地图底图、界面布局；交付可直接导入的资源及样例，不要求独立写玩法代码 |
| 成员3：程序 | 居民与工作系统 | 岗位、四邻格寻路、实体搬运、统一生产流程、工具占用、认可招募、居民钱包与首批生活消耗、工作状态界面功能 |

### 24.2 成员1任务：让玩家能开始经营

| 编号 | 任务 | 具体交付 | 可现场验收的结果 |
|---|---|---|---|
| P1-01 | 建立共同工程与公共数据 | 确认Unity版本；可运行首区场景；统一游戏时间、物品编号、数量单位、容量和配方数据；成员3可调用库存取用与预留 | 两名程序打开同一版本工程可运行；暂停时工作时间与燃料消耗均不推进 |
| P1-02 | 主角移动与拾取 | 移动、交互、8容量背包、地面物品数量、向旧仓库转存；可拾取并持有手锯 | 拾取多少，地面少多少；满背包拒绝超量；转存后背包与仓库不重复有同一物品 |
| P1-03 | 网格建造 | 18×18产权区；木料地点、发电机的放置预览、旋转、占地、材料与空闲建设人员检查 | 产权外／重叠／物资不足不能建；有效建设扣一次材料；取消预览不扣物资 |
| P1-04 | 发电与简单连接 | 简陋发电机燃料缓冲、输出4、废木料／碎屑燃烧；可铺电线，把发电机接到现有路灯或住房 | 有燃料且连通才供电，线路断开失去供电；废木料1份对应120游戏秒，暂停不消耗 |
| P1-05 | 外销与第一张工资 | 仓库木板逐件售卖、玩家现金、600秒工资时钟、按人数生成账单、手动发薪及支付结果通知 | 原现金0；卖木板得到收入且库存减少；2名员工应发20，主角不计；连续按支付不重复扣款或入账 |
| P1-06 | 接入公共界面与集成 | 背包、仓库、建造菜单、现金、工资倒计时、开始／重开入口、开局男女主选择；接入成员2素材和成员3功能 | 两种主角均能从正常界面完成同一流程，使用同一能力与配方；发布可直接启动的试玩包，记录版本及已知问题 |

材料检查先统一支持主角背包及可访问仓库，生产供料必须由成员3做实际运输。旧仓库容量80，不把开局所有垃圾直接塞进去。公共数据与时间由成员1维护，成员3新增配方或物品先使用同一套编号及单位。

移动／拆除的材料和内容物规则、完整存档、工资不足后的累计暴动、销售技术等接入后续批次。本批工资不足至少记录未付款金额并显示原因，不能把支付失败当已发工资。外销从本批就采用木板基础3、最低1及现有逐件压价规则，避免用固定高售价调出一条临时现金流。

### 24.3 成员3任务：让居民能持续做事

| 编号 | 任务 | 具体交付 | 可现场验收的结果 |
|---|---|---|---|
| P3-01 | 主角与居民共用工作流程 | 人工岗位的进入、退出、计时与完成；先做木料4→木板3＋碎屑1，40秒；工具需要手锯 | 主角独自能做一批；换为居民同样产出；一份输入不会被两人同时加工 |
| P3-02 | 居民状态与指定岗位 | 空闲、去岗位、搬运、工作、等待状态；选居民后指派生产或搬运；工具唯一占用 | 同一人只有一个正在执行的任务；手锯被占用时另一地点等待；停止生产后操作工可回空闲 |
| P3-03 | 四邻格寻路及实体搬运 | 工人每趟8容量、速度0.8格／秒、装卸各2秒；从垃圾堆／仓库供料到设备，成品送仓库 | 工人实际走到取货点和工作点；背上有货才运送；建筑阻路显示无路径，不远程补料 |
| P3-04 | 生产缓冲及连续加工 | 木料地点两批输入／两批输出、领料预留、完成扣料出货、主动停产保留进度；简单优先级供料与归仓 | 原料到齐才加工；输出满停；归仓后恢复；取消未取货任务释放预留，不丢货、不复制产物 |
| P3-05 | 认可、招募与人员名册 | 发电机首次有效发电后触发认可；玩家选择0—5名首批居民加入；登记住房名额、员工名单和个人钱包 | 发电机尚未建成并有效发电时不能免费招募；只免招募费，工资仍计；可选2人，主角加5人不超过6床 |
| P3-06 | 最小生活与钱包衔接 | 主角和居民食物／水300秒真实消耗、饮水优先；首轮发薪前按已有免费政策；居民钱包接收真实工资 | 供给扣实物；2名员工发薪后各实际增加10；工资记录不被个人消费修改 |
| P3-07 | 工作状态界面与联调 | 选中居民／地点的岗位、当前配方、加工进度、缺料、缺工具、输出满、无路径提示；与成员1工资及库存联通 | 玩家能看出等待原因，能重新指定岗位或搬运解决，产物必须进入实际仓库才可外销 |

首批认可事件在主角建成发电机、补充燃料并实际产生电力时执行一次，沿用已确定的“完成发电机后获得认可”。接线到住房／路灯用于演示真实供电，不额外作为招募门槛；重复补料、接线或断线不刷新免费名额。

生活供给只取实际入仓的食品和水，不从垃圾堆远程领取。测试从地面收集这些物资；主角作为1人也需消费。首批成员P3-06需与成员1接通现有“首个发薪前免费、之后按个人钱包及供给政策”的支付与取物；租金、清洁、衣物、死亡、幸福度与完整暴动恢复按后续批次接入，第一批试玩在第一张工资到账后验收，不声称已覆盖长时间经营。

首批简单任务调度优先支持玩家指定生产与搬运，能持续执行并在暂停／缺料时等待。智能自动填岗、岗位抢占、维护与农业阶段性调度后续扩展。主角使用同一生产逻辑；玩家主动控制移动时退出岗位，不一边走路一边继续加工。

### 24.5 开工时一起定下的对接规则

建议开工前用约30—60分钟共同完成以下约定，随后三人同时开工：

| 共同事项 | 负责人及约定 |
|---|---|
| 工程、版本与文件共享 | 成员1建立或整理现有工程，确认同一Unity版本，给出可运行版本；采用团队已有版本管理方式 |
| 游戏时间 | 成员1提供唯一游戏时间；工作、移动、燃料、工资、消费统一使用；暂停不推进，2／3倍速一致 |
| 物品与库存 | 成员1提供统一数量、容量及工具实例；成员3只通过该接口预约、领取、完成加工和归仓，不复制第二套库存 |
| 工作调用 | 成员3提供“进入工作、停止工作、设置配方”的入口；成员1主角交互和界面使用同一入口 |
| 员工名单与钱包 | 成员3维护在职名单和钱包；成员1工资读取这一名单、返回真实支付结果，由钱包接收一次；主角不入工资名单 |
| 建筑与可走地面 | 成员1提供实体占格与站位；成员3寻路读取同一网格，建筑正面统一 |
| 视觉与界面 | 成员2统一像素风图标、建筑占格、角色脚底锚点和状态稿；成员1接主角移动摇晃，成员3接居民移动摇晃，两名程序各接自己负责的界面 |
| 场景修改 | 成员1管理最终集成场景；成员2交场景样例／视觉资源，成员3交居民与工作组件，减少同时改同一场景文件 |

成员3可先用临时场景验证生产和搬运，再接公共库存；集成验收必须用真实库存和实际地面物品。成员1先把接口和占位建筑交给成员3，成员2逐步替换视觉，避免等最终美术才开始联调。三人每天交能被别人打开验证的内容，而非只交截图。

### 24.7 共同验收清单

三人分别从新游戏走同一条路线，不靠编辑器填库存或临时加钱：

1. 初始现金0、背包容量8、旧仓库80；固定启动物资在垃圾堆地面，产权建设地324格。
2. 主角拾取手锯、木料与紧固件，建木料地点；一批木料4用40秒产木板3、碎屑1。
3. 收集发电机材料，建设、补燃料、铺线，现有住房／路灯有真实供电状态。
4. 认可后自主招募2人，加入工资名单且占住房；主角与2名员工总人口3。
5. 一人生产、一人搬运；实际送入原料并将至少3批产物归仓。停产、缺工具、输出满、无路径都能显示原因并处理。
6. 在仓库出售木板取得现金；首次员工加入600秒后生成应发20的账单，手动支付后两名员工各得10，玩家扣20且不重复入账。
7. 运行中食物、水按人口真实消耗；暂停时移动、生产、燃料、工资及消费均停止推进。恢复继续，不重复领物或出料。
8. 用2人招募和5人招募分别核对工资20／50与住房3／6人口；一次物资不足不能凭空完成建造或付款。

交付内容：可运行试玩包、对应工程版本、本批任务完成表、按重要性排序的已知问题，以及从新游戏到第一张工资的操作说明。成员1汇总，成员2和成员3提供各自状态与复现说明。本文件是任务分配，未声称已经创建Unity工程、制作资源或完成代码。

### 24.8 首批之后的接续顺序
