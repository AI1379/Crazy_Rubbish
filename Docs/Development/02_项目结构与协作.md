## Git 与保留的 Plastic SCM

2026 年 10 月 7 日改为以 Git 同步到公开仓库 [AI1379/Crazy_Rubbish](https://github.com/AI1379/Crazy_Rubbish)，使用 `main`。当前本地工作树整体作为 Git 起点，包含 M1 原型、策划、资源、配置和工具；不导入旧 UVCS 变更集历史。Plastic 保留原有工作区、待提交变化和集成包。

Git 与 Plastic 使用同一份本地项目文件，各自维护提交历史；Git Push 不触发 Plastic Checkin。`.gitignore` 排除 `.plastic`，`ignore.conf` 排除 `.git`，缓存与构建产物在两边均排除。不要将一个版本系统的内部记录提交给另一个。

### Git 与 LFS

首次克隆前运行 `git lfs install`，克隆后执行 `git lfs pull`。图片、模型、音视频和字体使用仓库内 `.gitattributes` 的 LFS 规则；源码、文档、Unity YAML 及 `.meta` 保留普通 Git 文本。当前的小型原型图片也统一遵循素材类型规则，后续添加更大的素材无需再迁移这些类型的历史。

- 新资源连同 `.meta` 一起提交，保留 GUID。
- 提交 ProjectSettings、Packages 和锁文件；Library、Temp、UserSettings、日志、测试结果与构建目录不入库。
- `git lfs ls-files` 查看 LFS 素材；添加未覆盖的新类型大文件时，先设置规则再提交。
- Git 空目录使用 `.gitkeep`，避免克隆后只有目录 `.meta` 而没有目录。
- 原始策划副本关闭文本换行转换，保持与输入文件逐字节一致。

LFS 配置方式依据 [GitHub 官方说明](https://docs.github.com/en/repositories/working-with-files/managing-large-files/configuring-git-large-file-storage)。

### 保留的 UVCS 工作区

沿用工作区 `Crazy_Rubbish-Crazy_Rubbish`，目录为 `D:\Projects\Crazy_Rubbish`，云仓库为 `Crazy_Rubbish/Crazy_Rubbish`，初始分支为 `/main`。Unity Editor 已加入 `com.unity.collab-proxy` 2.7.1，可通过 `Window/Unity Version Control` 打开版本控制窗口，也可以使用独立 Plastic 客户端。

在 Plastic 中，新增文件或目录先 Add，再在 Pending Changes 中核对后 Checkin。当前工作区直接连接云仓库，Checkin 即上传变更集。当前以 Git 上传为本次交付，不自动追加 Plastic Checkin。

- 提交 `Assets` 内资源与 `.meta`，保持 GUID 与引用稳定。
- 提交 `ProjectSettings`、`Packages/manifest.json`、`Packages/packages-lock.json`。
- 不提交 Library、Temp、Logs、UserSettings、构建输出或测试结果；`ignore.conf` 已设置。
- 场景、Prefab、ScriptableObject 使用文本序列化；资源元数据可见。
- `.plastic` 是本机工作区记录，不上传；Plastic 能跟踪空目录，Git 用 `.gitkeep` 保留相同的目录结构。
- 新素材按实际来源保留必要许可文件；当前基础场景来自本机 Unity 官方 2D 模板。

## 本地工具

```powershell
.\Tools\Unity.ps1 -Action Import
.\Tools\Unity.ps1 -Action Open
```

`Import` 在 Unity Editor 关闭本项目时以批处理模式导入和检查编译；`Open` 打开项目。脚本默认依据 `ProjectVersion.txt` 查找 Hub 安装，也支持 `-UnityPath`。日志在 `Logs/`，不提交。

最终发布平台由团队确认。当前提供 Windows 64 位开发原型用于验证，输出在忽略的 Builds/Windows 中，不作为最终比赛提交包。
