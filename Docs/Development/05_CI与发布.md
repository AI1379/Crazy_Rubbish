# CI与Windows发布

2026-10-08。当前M2已先独立提交；本次流水线和发布入口另外提交。GitHub Actions负责构建并附加到用户发布的Release，不自动创建新Release。

## 流程

| 触发 | 工作流 | 结果 |
|---|---|---|
| main推送、main目标PR、手动运行 | CI checks | actionlint 1.7.12检查YAML；PowerShell语法、版本输入和ZIP完整性检查，不需要Unity凭据 |
| 发布正式版或预发布Release | Windows release | 使用该tag的提交：Unity EditMode测试→Windows x64 Mono正式构建→Windows无图形运行验收→ZIP与SHA-256→附加到触发Release |
| 手动运行Windows release | 相同测试、构建和验收 | 只提供Actions artifacts，不创建或修改Release |

轻量CI通过不代表云端Unity测试通过。Unity测试和Windows构建只在Windows release工作流执行。

Unity版本从ProjectSettings/ProjectVersion.txt读取，目前2022.3.62f3。Unity测试及交叉构建使用Ubuntu runner和GameCI；构建后在windows-2022 runner实际运行Windows玩家包。缓存区分Linux EditMode与Windows Mono，素材使用Git LFS拉取。第三方Actions固定到已查询的提交SHA。

## Personal授权

当前用户选择Unity Personal，并要求暂时先上传workflow，之后补凭据。仓库尚无Unity Secrets，本机标准位置也未发现.ulf；没有读取或上传其他本机凭据。

在[Actions Secrets](https://github.com/AI1379/Crazy_Rubbish/settings/secrets/actions)设置：

| Secret | 内容 |
|---|---|
| UNITY_EMAIL | Unity账号邮箱 |
| UNITY_PASSWORD | Unity账号密码 |
| UNITY_LICENSE | Personal .ulf文件完整内容 |

依[GameCI Personal授权说明](https://game.ci/docs/github/activation/)，在Unity Hub取得许可文件；Windows标准位置为C:/ProgramData/Unity/Unity_lic.ulf。没有生成.ulf时按该说明处理Hub授权方式。凭据只填GitHub Secrets，不提交到源码或写入聊天。

缺少任一Secret时，Windows release在下载Unity镜像前明确失败，构建和附件上传均不执行。设置好后可先在[Windows release Actions页面](https://github.com/AI1379/Crazy_Rubbish/actions/workflows/windows-release.yml)手动运行确认。

## 发布与版本

Release tag使用v0.2.0、0.2.0或v0.2.0-rc.1这样的格式。路径、空白及Shell特殊字符拒绝进入包名。构建内Application.version去除v前缀，文件名保留tag版本：

```text
CrazyRubbish-v0.2.0-Windows-x64.zip
CrazyRubbish-v0.2.0-Windows-x64.zip.sha256
```

ZIP根目录包含CrazyRubbish.exe、UnityPlayer.dll、CrazyRubbish_Data、MonoBleedingEdge、字体授权和build-info.json，不是单个EXE。build-info记录tag、提交SHA、Unity版本、Mono后端和非Development模式。ZIP下载后解压整个目录再运行。

手动运行可填version，空值生成0.0.<run_number>-ci快照。手动运行不发布附件；Release事件成功后使用GITHUB_TOKEN上传ZIP及校验文件，重跑替换同名附件。只有上传job有contents:write，其余job只读。订阅release.published同时覆盖正式版及预发布，见[GitHub事件文档](https://docs.github.com/en/actions/reference/workflows-and-actions/events-that-trigger-workflows#release)。

## 本地验证与操作

```powershell
.\Tools\CI\TestPipeline.ps1
$actionlint = .\Tools\CI\GetActionlint.ps1
& $actionlint -shellcheck=
.\Tools\Unity.ps1 -Action Test
.\Tools\Unity.ps1 -Action Release -ReleaseVersion '0.2.0'
.\Tools\CI\SmokeWindows.ps1 -ExpectedVersion '0.2.0'
$commit = git rev-parse HEAD
.\Tools\CI\PackageWindows.ps1 -Version 'v0.2.0' -Commit $commit
```

正式构建单独输出Builds/WindowsRelease；原开发构建仍在Builds/Windows。正式构建不带Development标记并在结束后还原本地PlayerSettings版本。打包拒绝覆盖已存在ZIP，可指定新的OutputDirectory；输出不能放在源玩家目录内部。

无图形验收使用-batchmode -nographics，不依赖截图或显卡。它检查5名居民、5000分真实发薪、至少12批木工、重开、实际Application.version及非Development标记。每次用新报告路径，防止旧结果冒充成功；超时或退出失败阻止上传。

本轮本地已通过32项Unity规则测试、23项脚本/打包检查、actionlint检查、非Development正式构建、原玩家及ZIP解压后玩家的无图形运行验收。两个运行均报告版本0.0.0-ci-local、5名居民、5000分工资与12批生产。GameCI所需2022.3.62f3 Windows Mono镜像已确认存在；推送后的轻量CI结果见GitHub Actions。

云端Unity授权、Linux交叉构建及真实Release附件上传尚未验证；补齐Secrets后首次手动运行验证，再发布正式Release。Logs、TestResults、Artifacts和Builds均保持忽略，不提交构建缓存、验证包或下载的检查工具。
