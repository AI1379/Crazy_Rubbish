# 长局经营验证与调度修复（2026-10-18）

本期按“整局试玩与平衡”的方向，先处理从零资金起步到二区的经营阻塞。新增可重复的经营脚本，记录实际走路、拾取、加工、搬运、发薪、交易和扩区；修复调度错误后，再对照不同投资顺序。本期没有改动商品价格、工资、配方时长、科技条件或地价。游戏仍无总时长限制。

## 本期进展

### 已修复的可玩性问题

1. **种子可以真正投入种植。** 生活保护规则仍禁止卖掉保留种子，但允许工人把种子运到种植地点。原来会出现仓库有种子、种植地点一直缺种子的情况。
2. **原水按真实生产批次搬运。** 取水一次产生6升合格原水，保留这一批的来源品质与独立标识；不再拆成六个只能分别搬运的实例。背包和工人载重、运输耗时与预约照常计算。旧档中的小批次不强制合并，传送带仍按自身速率搬运。
3. **生产地点可以直接供料。** 工人可从另一设施的产出缓冲区取货，送往实际需要的设备，经过完整取货、步行、卸货过程。无需所有中间产物都先入仓。
4. **补给按实际紧急程度排序。** 仓库食水不足一轮时先补生活物资，再安排必要工具、紧急食水生产原料及即将耗尽的发电燃料。正常配方先补齐一批全部投入，之后再预送第二批；缺一种原料时不反复搬运另一种原料挤占运力。保留玩家工作优先级在同类任务中的作用。
5. **原水缓冲不再无限挤占搬运。** 下游原水已有约两批所需库存及在途预约时，可把多余原水留在取水设施中，形成正常的产线背压。工人不再无休止把原水搬进仓库。手动取货和传送带仍可使用；没有删除或免费转移物品。
6. **损坏工具不占正常工具补给。** 只派送仍有耐久的工具，避免坏锯反复运到岗位。停止的旧产线不再驱动自动购买备用工具；已在途中或已买下的工具不退钱。
7. **建设和移动保护已有设施操作侧。** 新设施不能直接盖住另一非线路设施的工作入口，预览与实际建设使用相同检查。电线、传送带和接口仍可按原规则叠加。这项检查不保证任意复杂围墙布局下的全局可达性。

### 经营对照方法

脚本从默认零资金和默认来料开始，只使用公开的玩家操作。不注入钱、物品、科技、人口，不传送角色、不跳过时间、不关闭饥渴、工资、耐久或结局。主角实际到现场拾取、存取和加工；其他居民使用游戏里的实际搬运和生产规则。经营期间每个游戏秒检查售卖盈余和补发欠薪，属于熟练、频繁管理的策略，不能当作普通玩家的实际完成时长。

| 路线 | 人手及设施 | 用途 |
|---|---|---|
| 手工经营 baseline-final | 两名员工，手工木工、发电、扩仓，保留12块木板 | 检查零资金循环、实物收入与扩区资金 |
| 分步半自动 semi-final | 三名员工，实际拆旧设备建电动木工，保留6块木板，启用已有自动食水采购和工具采购 | 分离半自动木工与全套生活产线的投入负担 |
| 提前铺开生活线 managed-four-final | 半自动木工、采水净化、种植灯、种植、厨房，建齐后四名员工 | 检查种植实产、生活供给与过早多线投资的压力 |

不同路线的招募人数、预留建材和采购策略不同，不能把它们的差额直接解释为某一设备的收益率。对照关注能否推进、真实瓶颈及投资顺序。脚本购买二区前额外保留下一次全员工资；游戏本身仍只检查200钱地价。因此同时记录“首次够地价”和“带工资储备实际购买”两种时间。

原始记录含来料种子、核心及配置哈希、五分钟间隔台账、设施状态、运输任务、阶段存档、实际批次、工人工作时间与资金核对。正式交付附经营记录表和原始JSON。手工、提前铺开生活线各测试三个种子，分步半自动另测一个，共七次。提前铺开生活线三个种子首次够地价约104—153分钟，带下期工资扩区约122—174分钟；这表明来料与运输差异会显著影响资金积累。仅最终同一核心版本的记录用于本期结论；早期排错时改变过策略的记录不作严格前后对照。

### 实测观察与当前建议

- 三个种子4271、1379、42的手工路线，首次攒够地价约50—53游戏分钟。脚本频繁售卖、熟悉初始物资位置，正常玩家可能更慢。工具损耗仍然存在，后续必须补充工具或升级。
- 种子4271的分步半自动路线首次够地价约55分钟，保留工资后约65分钟购买二区。两小时内实际完成121批电动锯板；机器维护仍占用一名员工。这个结果不能外推到所有布局。
- 同一种子提前铺开全套食水和种植线，约32分钟建齐，首次够地价约153分钟，保留工资后约174分钟扩区；已经实际收获并熟制食物，但资金与人工物流负担明显更大。增加员工也增加工资，不能把招人当作无成本的吞吐提升。
- 一块种植床仍只有约0.62份食物/分钟的理想上限，且会受光照、浇水、人力和物流影响；四员工加主角约需1份/分钟。因此这一条小型产线是补充供给，记录中仍有垃圾食物回收和采购，**没有证明食物自给**。

建议先保障饮水、库存和当期工资，再逐段扩生产；一台半自动设备要同时考虑维护岗位与实际搬运距离。厨房、净化和种植可以分步建立，保留外购或回收作为补充。这些提示已加入教程，当前生活线目标改为提醒逐步投入。是否扩区仍由玩家决定，不增加教学硬门槛，也不强迫玩家先造齐生活设施。没有根据单一脚本直接提高售价、免除维护或下调工资。

## 问题与风险

全套生活产线的早期投资负担仍偏重，收益取决于距离、岗位、粮水库存和来料；本期修复保证流程可运行，不代表全局经济已经平衡。手工与半自动对照包含不同管理策略，不能声称自动化必然更赚钱。

本期经营记录覆盖零资金开局到二区与持续经营，尚未覆盖零资金一路制造返程载具的完整经济闭环，也不等同人工整局试玩。既有三区矿料到返程的完整配方链隔离回归、实际结局和存档回归继续保留。测试脚本的120/180分钟观测窗口仅用于收集记录，不是游戏时长限制。

本机验证编辑器为2022.3.22f1；正式工程目标仍为2022.3.62f3。旧档兼容规则与个人存档目录未改动。

验证结果：233项规则回归全部通过；Windows构建和场景检查通过。在1280×800、1920×1080均完成运行回归并查看截图，包含既有自动化、教程、生产查阅及返程结局。实际经营184分钟的二区记录已经过逐字段存盘、读取核对并继续运行：物资数量、资金、人口、在制品与运输预约保留。浮点字段按极小舍入容差比较，整数台账严格比较。新增经营复现工具重跑分步半自动种子4271，扩区时间与资金结果一致。

## 下期计划

优先对生活产线做距离和投资顺序对照，再检查二区高值产品与工资支出能否支撑三区及返程工程。需要沿完整主线持续经营，单独观察垃圾积压、价格恢复、工具耗尽与后期维护人手。在取得更多同策略数据前，保留当前基础经济数值。

复现入口：先用Unity导入工程，再运行 `Tools/RunBalanceAudit.ps1 -UnityPath <Unity.exe绝对路径>`。默认执行三种策略与三个来料种子，输出到 `Artifacts/BalanceAudit`，不读写个人存档。Windows运行回归可加 `-planSmoke -planBalanceSnapshot <阶段或最终存档>` 检查真实经营记录的保存、读取与继续运行；该入口仅在测试参数下启用。
